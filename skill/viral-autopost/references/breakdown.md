# 拆解方法

先读 config/profile.md，再判断这条内容是否适合它的读者。只有标题时，只分析标题，不猜正文事实。

从六类里选最贴近的一类，保存 hook_type：

| 类型 | 起作用的地方 |
| --- | --- |
| 晒结果+反转 | 先让人看到结果，再把原因拉回一个容易忽略的动作 |
| 数据冲击 | 数量或比例打破预期，让人想知道怎么做到 |
| 反差转变 | 同一个问题前后两种状态，让人追问转折 |
| 金句 | 一句可独立理解的观点，引出解释 |
| 权威+观点 | 可信来源给判断提供依据，但不替代证据 |
| 痛点+悬念 | 描述读者遇到的具体困难，延后揭示办法 |

开头公式：话题（讲什么）+钩子（为什么继续看）+可信度（有什么可核对的依据）。
用自己的话写公式，不引用原句。拆出 1–6 个节拍，例如：困境 → 意外结果 → 转折原因 → 方法 → 限制 → 收尾。

给用户看四件事：钩子是什么、开头怎么起、内容怎样一步步推进、可能为什么火。
“为什么火”写成假设：哪类读者、什么处境、满足什么心理。没有互动数据就不要声称已证明因果。
结合 profile 给 1–2 个可借用结构的新主题。

风险提示：无法核实的数据、私人经历、未经授权的截图、夸大承诺、诱导互动、制造焦虑。标出不能直接挪用的素材。
记录格式：日期、来源、hook_type、开头公式、结构节拍、有效原因假设、新主题、risk_flags。
